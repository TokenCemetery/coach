# Исследование совместимости с Emby

Дата: 2026-09-18. Статус: предварительное исследование; публичный API и HTML живого Emby проверены, авторизованные сценарии ещё не исследованы.

## Подтверждённые факты

- На старте исследования проект `coach` был пуст. Сейчас реализован первый Go API-срез; границы проверки описаны в [VALIDATION.md](VALIDATION.md). Git-коммиты не создавались.
- Исходники Jellyfin доступны в `/Users/olegshulyakov/Projects/GitHub/jellyfin/jellyfin`, commit `50866380c95758244f79bd4fbb01b9474e80bd81`.
- `SharedVersion.cs` содержит `13.0.0`. Это версия исследуемого checkout, а не подтверждение стабильного релиза.
- В `Jellyfin.Api/Controllers` найдено 60 контроллеров. Исследованы маршруты основных сценариев и несколько моделей; полный аудит кода не проводился.
- README прямо отделяет сервер от `jellyfin-web`: исходники frontend в выгруженном репозитории отсутствуют.
- `LICENSE` содержит GNU GPL version 2. Лицензия нового проекта и условия использования стороннего кода пока не выбраны.
- Имя `ds918.local` не разрешилось. Адрес `http://192.168.1.11:8096/` доступен, в том числе из sandbox (проверено 2026-09-19; ранее соединение изнутри sandbox не устанавливалось).
- Встроенный браузер выполняет Emby Web 4.10.0.40 без изменений его кода. Это сделало возможной браузерную приёмку, ранее заблокированную отказом browser runtime.
- С разрешения пользователя снят авторизованный эталонный контракт: 30 очищенных фикстур в `docs/fixtures/emby-4.10.0.40/`. Сессии съёма закрыты, отзыв токенов подтверждён.
- Эталон использует короткие числовые строковые `Id` и отдельный `Guid`; у коллекций `Guid`, `PresentationUniqueKey` и `DisplayPreferencesId` совпадают. Даты — .NET-формат с семью знаками дробной части. Coach сохраняет собственные стабильные hex-идентификаторы: клиенты работают с `Id` как с непрозрачной строкой.
- `GET /System/Info/Public` и `GET /emby/System/Info/Public` вернули HTTP 200 и одинаковый JSON: версия `4.10.0.40`, имя сервера `DS918+`, строковый `Id`, пустые массивы `LocalAddresses` и `RemoteAddresses`. Идентификатор экземпляра здесь не сохраняется.
- `GET /` вернул HTTP 302 с `Location: web/index.html`; целевая страница вернула HTTP 200. HTML содержит `data-appversion="4.10.0.40"`, `data-culture="ru"`, `lang="ru"` и ссылку `apploader.js?v=4.10.0.40`. Это версия, объявленная страницей; выполнение JavaScript и вход не проверены.
- Import map страницы ссылается на `modules/emby-apiclient/apiclient.js`, `connectionmanager.js` и `modules/browserdeviceprofile.js`. API-клиент, fetchhelper и querystring исследованы и выполнены против Go-сервера; connection manager и browser device profile ещё не проверены.
- Коллекция, производительность, ОС, аппаратное обеспечение и версии остальных клиентов неизвестны. Имя `DS918+` само по себе не подтверждает модель устройства.

## Источники контрактов

Наблюдения текущего Emby Web: API-клиент добавляет `/emby`, использует разный регистр путей, передаёт данные устройства и токен через query `X-Emby-*`, выполняет вход формой `Username`/`Pw`. Для JSON-запросов fetch-обёртка заменяет content type на `text/plain` и добавляет `reqformat=json`. Настройки версии 4.10 читаются через `/usersettings/{id}`, частичное обновление — `/usersettings/{id}/Partial`.

Публичный `/Users/Public` эталона возвращает массив; у наблюдённой записи есть `Name`, `ServerId`, `Prefix`, `Id`, `HasPassword`, `HasConfiguredPassword`, `LastLoginDate`, `LastActivityDate`. Персональные значения не сохранялись. `/Branding/Configuration` вернул пустые `LoginDisclaimer` и `CustomCss`.

Для каждого поведения фиксируем источник: наблюдение конкретного Emby, официальная документация или реализация Jellyfin. Совпадение маршрутов не доказывает совместимость ответов и поведения.

| Область | Jellyfin: путь относительно checkout | Что проверить на Emby |
|---|---|---|
| Информация о сервере, вход | `Jellyfin.Api/Controllers/SystemController.cs`, `UserController.cs` | Обязательные поля, версия, идентификатор сервера, ошибки входа |
| Авторизация | `Jellyfin.Api/Auth/CustomAuthenticationHandler.cs` | Схемы заголовков, привязка токена к пользователю и устройству, отзыв |
| Библиотека | `Jellyfin.Api/Controllers/ItemsController.cs`, `UserLibraryController.cs`, `UserViewsController.cs` | Фильтры, сортировка, пагинация, пустые результаты, права |
| Сериалы | `Jellyfin.Api/Controllers/TvShowsController.cs` | Сезоны, эпизоды, следующий эпизод |

Официальная [документация Emby REST API](https://dev.emby.media/doc/restapi/index.html) описывает префикс `/emby`, JSON/XML и API Browser. Какие варианты использует целевой клиент, нужно записать в матрицу совместимости.

В [описании авторизации](https://dev.emby.media/doc/restapi/User-Authentication.html) указаны `/Users/Public`, `/Users/AuthenticateByName`, `Authorization: Emby …`, `X-Emby-Token` и отзыв токена через `/Sessions/Logout`. Это исходный контракт для проверки, а не наблюдение нашего экземпляра.

[Документация PlaybackInfo](https://dev.emby.media/reference/RestAPI/MediaInfoService/postItemsByIdPlaybackinfo.html) связывает профиль устройства и выбор дорожек с возвращаемыми источниками, идентификатором сессии и URL воспроизведения. Простого ответа со ссылкой на файл недостаточно для покрытия этих сценариев.

## Рассмотренные подходы

| Подход | Преимущество | Цена / ограничение |
|---|---|---|
| Go-сервер по контрактам Emby, Jellyfin как справочник — рекомендация | Можно проверять совместимость и ресурсы по небольшим завершённым сценариям | Требуется исследование фактических запросов и различий версий |
| Последовательный перенос подсистем Jellyfin на Go | Готовые примеры сложной медиалогики | Большой объём; перенос не доказывает совместимость с современным Emby |
| Go-прокси перед Jellyfin | Быстрый эксперимент с переводом API | Остаются .NET-сервер и его потребление ресурсов; не конечное решение |

Предлагаемая начальная архитектура: один Go-процесс, локальное хранилище данных, FFprobe/FFmpeg для медиа, ограниченные фоновые очереди. Выбор БД и библиотек отложен до требований первого сценария. Микросервисы для него не обоснованы.

## Следующее исследование

1. Использовать проверенный адрес `http://192.168.1.11:8096/` для дальнейшего исследования; публичная информация уже прочитана.
2. Зафиксировать версии остальных целевых приложений; сервер и HTML Emby Web объявляют `4.10.0.40`.
3. Записать запросы и ответы сценариев входа, просмотра библиотеки и воспроизведения; отдельно WebSocket и поведение плеера.
4. Хранить только очищенные фикстуры: без паролей, токенов, персональных названий и путей. Для связанных ID сохранять согласованное отображение.
5. Для сценариев с изменением состояния использовать согласованного тестового пользователя и тестовую библиотеку; не повторять записи на рабочем экземпляре автоматически.
6. Снять исходные показатели ресурсов и определить конкретную нагрузку для сравнения.

## Открытые решения

### Контракт начального каталога

Методы оригинального `apiclient.js` проверены чтением с эталона: `getItems(userId, options)` вызывает `/Users/{id}/Items` либо `/Items`; `getItem(userId, itemId)` — соответствующий маршрут карточки; `getLatestItems(options)` возвращает ответ `/Users/{id}/Items/Latest`. Это сведения о запросах клиента, не авторизованное наблюдение ответов рабочего Emby.

Маршруты и поля сверены с [ItemsService](https://dev.emby.media/reference/RestAPI/ItemsService/getItems.html), [UserLibraryService](https://dev.emby.media/reference/RestAPI/UserLibraryService/getUsersByUseridItemsById.html) и локальными контроллерами Jellyfin. В Coach реализован ограниченный набор фильтров; неизвестные возвращают 400. Временный DateCreated из mtime не заявляется идентичным истории Emby.

Технические метаданные получает [FFprobe](https://ffmpeg.org/ffprobe.html). Для передачи открытого файла выбран [протокол fd](https://ffmpeg.org/ffmpeg-protocols.html#fd): он поддерживает seek у обычного файла и позволяет запретить остальные протоколы. Открытие ограничено [os.Root](https://pkg.go.dev/os#Root); это не защита от уязвимостей нативного декодера и не изоляция mounts/hardlinks.

### Что ещё требуется определить

- Пользователь подтвердил: первым клиентом является встроенный Emby Web. Приоритет остальных приложений пока не выбран.
- Целевая платформа: `ds918` в hostname недостаточно для вывода о модели NAS, CPU, ОС и аппаратном ускорении.
- Размер библиотеки, число одновременных потоков, используемые форматы и наблюдаемые сбои Emby.
- Лицензия и модель распространения; происхождение используемых исходников и frontend-ресурсов фиксируется до их включения в проект.
- Нужен ли перенос пользователей, истории и настроек. Совместимость API сама по себе не означает совместимость базы данных.

Связанные документы: [требования](../PRD.md), [roadmap](../ROADMAP.md).

## Уточнение PlaybackInfo и локальный UI (2026-09-19)

В оригинальном `apiclient.js` метод `getPlaybackInfo(itemId, options, deviceProfile)` отправляет options через query, а DeviceProfile — в JSON. Ранее Coach учитывал только профиль из тела. Теперь оба источника параметров проверяются; конфликтующие значения отклоняются.

`browserdeviceprofile.js` 4.10.0.40 содержит CodecProfiles для Video/VideoAudio: ограничения уровня/профиля H.264, ширины, битрейта, тегов HEVC, числа аудиоканалов и IsSecondaryAudio. IsRequired встречается как boolean и строка `"false"`, Value — как строка и число. Эти формы покрыты тестами. Схемы и код ошибки NoCompatibleStream сверены с [официальным PlaybackInfo API](https://dev.emby.media/reference/RestAPI/MediaInfoService/postItemsByIdPlaybackinfo.html). Семантика ApplyConditions и отсутствующих обязательных значений сверена с локальными моделями Jellyfin; она не считается авторизованным наблюдением современного Emby.

Пользователь предоставил `../emby-webui`. SHA-256 модулей apiclient/fetchhelper/querystring совпадают с ранее проверенными ресурсами 4.10.0.40. Локальный index.html содержит исходный `<html>` без data-appversion; apploader.js читает этот атрибут для dashboardVersion и версии кеша. Адаптер `-web-dir` добавляет атрибут в HTTP-ответ, не меняя файлы. Сам frontend не скопирован в проект Coach.

Повторная браузерная проверка сейчас недоступна: подключение к встроенному браузеру отклонено. Проверка локального UI ограничена выдачей ресурсов и выполнением оригинальных API-модулей без DOM/плеера.
